# shxin.blog

정적 블로그. `posts/`의 Markdown 파일을 읽어 라우트별 HTML을 완성된 형태로 생성하고, `dist/`를 그대로 서빙합니다. 브라우저는 이미 렌더링된 페이지를 받으므로 JavaScript가 꺼져 있어도 글을 읽을 수 있습니다 — 수식과 문법 강조까지 포함해서입니다.

빌드에 쓰는 의존성은 두 개뿐이고, 둘 다 읽는 쪽으로 나가지 않습니다.

| 꾸러미 | 하는 일 | 나가는 것 |
| --- | --- | --- |
| `katex` | 빌드 시점에 수식을 조판 | 글자 모양을 지는 스타일시트와 글꼴뿐 (`dist/katex/`) |
| `highlight.js` | 빌드 시점에 코드를 토큰으로 나눔 | 없음. 배색은 `style.css`가 진다 |

파서·표·그래프·다이어그램·참고문헌·이미지 크기 판독은 모두 이 저장소의 코드입니다.

## 사용법

```bash
npm install       # nodemon (개발용) 설치
npm start         # 빌드 후 http://localhost:8002 에서 서빙
npm run dev       # 소스 변경 감지 후 자동 재빌드·재시작 (캐시 끔)
npm test          # 파서 · 빌드 · 서버 테스트
npm run build     # dist/ 생성만
npm run serve     # 기존 dist/ 서빙만
npm run lint      # 빌드하면서 콘텐츠를 점검하고, 오류가 있으면 1로 끝냅니다
```

`npm run dev`는 `DEV=1`로 서버를 띄우므로 CSS·JS도 캐시되지 않습니다. 바뀐 내용을 보려고 강력 새로고침(Ctrl+Shift+R)을 할 일이 없고, 평범한 새로고침이면 됩니다. `draft/`를 보려면 `POSTS_DIR=draft npm run dev`.

### 편집기 (`/write/`)

`npm run dev`로 띄운 서버에는 `http://localhost:8002/write/`에 편집기가 있습니다. 왼쪽에 문법 삽입 팔레트, 가운데 원고, 오른쪽에 실시간 미리보기가 섭니다.

미리보기는 브라우저가 그리지 않습니다. 원고를 서버로 보내면 서버가 **빌드와 같은 함수**로 조판해 돌려줍니다 — `data/*.csv`를 읽고, 그림 크기를 재고, 수식을 KaTeX로 굽고, `postPage()`로 글 머리와 목차까지 세우는 일이 전부 빌드와 같은 자리에서 일어납니다. 그래서 미리보기와 실제로 나갈 글이 어긋날 수 없고, 화면 아래 lint 줄도 `npm run lint`가 내는 것과 같은 결과입니다.

팔레트의 항목은 `SYNTAX.md`가 적어 둔 문법 전부를 덮습니다. 누르면 커서 자리에 예제 골격이 들어가고, 블록 문법은 앞뒤로 빈 줄을 알아서 확보합니다. `site/editor.mjs`가 그 목록이고, 시험이 조각 하나하나를 실제로 렌더해 보므로 문법이 바뀌었는데 팔레트가 그대로면 `npm test`가 깨집니다.

이름(slug)을 적고 저장하면 `draft/<slug>.md`가 생기고, nodemon이 그것을 보고 다시 구워 `/<slug>/`에 실제 글로 섭니다. 저장 전 원고는 브라우저에 남으므로 새로고침해도 사라지지 않습니다.

편집기와 그 저장 경로는 `DEV=1`일 때만 존재합니다. 나가는 빌드에는 페이지도, `editor.js`도, `editor.css`도 들어가지 않고 배포 서버는 `GET`·`HEAD`만 받습니다. 쓰기 경로가 열려 있는 동안에는 서버가 `127.0.0.1`에만 묶이므로, 다른 기계에서 보려면 `HOST=0.0.0.0 npm run dev`로 직접 열어야 합니다.

Docker:

```bash
docker build -t shxin-blog .
docker run --rm -p 8002:8002 shxin-blog
```

Docker 개발 서버(8003 포트):

```bash
docker build -f Dockerfile.dev -t shxin-blog-dev:local .
docker run -d --name shxin-blog-dev --init --restart unless-stopped \
  -p 8003:8003 -e OUT_DIR=dist/site \
  --mount "type=bind,src=$(pwd),dst=/app" \
  --mount type=volume,dst=/app/node_modules \
  --mount type=volume,dst=/app/dist \
  shxin-blog-dev:local
```

소스 변경은 자동으로 다시 빌드되며 `/write/`에서 초안을 편집할 수 있습니다.
의존성과 빌드 결과는 컨테이너용 볼륨에 두고, 초안은 프로젝트의 `draft/`에 저장합니다.
로그는 `docker logs -f shxin-blog-dev`, 중지는 `docker stop shxin-blog-dev`로 확인합니다.

## 환경 변수

| 변수       | 기본값               | 용도                                                    |
| ---------- | -------------------- | ------------------------------------------------------- |
| `PORT`     | `8002`               | 서버 포트                                               |
| `SITE_URL` | `https://shxin.blog` | canonical · Open Graph · RSS · sitemap에 쓰이는 절대 주소 (빌드 시) |
| `OUT_DIR`  | `dist`               | 빌드 출력 경로 (테스트가 격리용으로 사용)               |
| `POSTS_DIR` | `posts`             | 빌드가 읽을 글 경로 (`draft/` 미리보기와 테스트 샘플용) |
| `DRAFT_DIR` | `draft`             | `DEV=1`일 때 함께 굽고, 편집기가 저장할 초안 경로 |
| `DEV`      | (없음)               | `1`이면 서버가 아무것도 캐시하지 않고 `/write/` 편집기가 섭니다. `npm run dev`가 자동으로 켭니다 |
| `HOST`     | `0.0.0.0` (`DEV=1`이면 `127.0.0.1`) | 서버가 묶일 주소. dev에서는 쓰기 경로가 열리므로 이 기계 안으로 좁힙니다 |
| `LINT_EXIT` | (없음)              | `1`이면 콘텐츠 lint에 오류가 있을 때 빌드가 종료 코드 1을 냅니다 (`npm run lint`) |

## 글 쓰기

`posts/` 아래에 `.md` 파일을 만들고 상단에 frontmatter를 넣습니다.

```markdown
---
title: "글 제목"
date: 2026-07-29
updated: 2026-08-14
category: infra
slug: my-post
description: "목록과 검색 결과에 노출되는 한 줄 요약."
keywords: 사설 CA, HTTPS, step-ca
series: "사설 CA 세우기"
part: 2
---

본문을 여기에 씁니다.
```

- `updated`는 고친 날입니다. 적으면 글 머리에 "고침"으로 나오고 sitemap의 `lastmod`가 그 날로 갑니다. 적지 않으면 쓴 날이 곧 고친 날입니다.
- `slug`을 생략하면 파일명이 주소가 됩니다. 글은 `/{slug}/`에서 읽습니다.
- `description`을 생략하면 본문 앞 두 문장을 자동으로 사용합니다. 물러난 것이지 고른 것이 아니므로 lint가 알려 줍니다.
- `series`를 적으면 그 글이 시리즈에 들어갑니다. `part`가 편 순서를 정하고, 생략하면 날짜순입니다. 자세한 것은 [시리즈](#시리즈)에.
- `bib`으로 그 글이 볼 참고문헌 파일을 바꿀 수 있습니다. 기본값은 `refs.bib`입니다.
- `keywords`는 쉼표로 구분합니다. `<meta name="keywords">`로 나가고, 글 페이지에서는 초록 바로 아래 `Keywords` 줄로 보이며, 낱말마다 `/keyword/{슬러그}/` 목록으로 갑니다. 분류는 글 하나에 하나뿐이지만 키워드는 여러 글이 나눠 쓰므로 실제 진입로는 이쪽입니다. 생략하면 아무것도 나오지 않습니다.
- `category`를 생략하면 `Uncategorized`로 분류되며, 카테고리 목록은 `/category/{categorySlug}/`에 자동 생성됩니다.
- `date` 기준 내림차순으로 정렬됩니다.
- 아직 내보내지 않을 글은 `draft/`에 둡니다. 빌드는 `posts/`만 읽으므로 사이트에는 나가지 않고, `POSTS_DIR=draft npm run build`로 따로 확인합니다. `chart` 문법을 넓게 훑는 `draft/chart-test.md`가 여기 있습니다.
- 문법을 전부 한 페이지에 모아 둔 글은 `posts/all-syntax.md`입니다. 조판을 바꾸면 여기부터 봅니다. 마지막 절이 일부러 틀린 문법이라, 이 글이 있는 한 lint는 일곱 건(오류 4 · 경고 3)을 뱉고 `npm run lint`는 종료 코드 1을 냅니다.

## 지원하는 Markdown 문법

| 요소        | 문법                                            |
| ----------- | ----------------------------------------------- |
| 제목        | `#` ~ `######` (페이지 `<h1>` 아래로 한 단계씩) |
| 강조        | `**굵게**`, `*기울임*`, `~~취소~~`, `==형광==`, `^위^`, `~아래~` |
| 코드        | `` `인라인` ``, ```` ```언어 ```` 블록          |
| 목록        | `-`/`*`/`+`, `1.` — 두 칸 들여쓰기로 중첩       |
| 할 일 목록  | `- [ ]`, `- [x]` — 상자는 잠겨 있음             |
| 링크        | `[글자](주소)`, 참조식 `[글자][이름]` + `[이름]: 주소 "제목"` |
| 표          | `\| 칸 \|` + `\| --- \|` 구분선 (헤더 행 없음)  |
| 그래프      | ```` ```chart {type=line} ```` 블록 + 파이프 격자 |
| 인용        | `> 인용`                                        |
| 알림 상자   | `> [!NOTE]`·`TIP`·`IMPORTANT`·`WARNING`·`CAUTION`·`DETAILS` |
| 구분선      | `---`                                           |
| 각주·참고문헌 | 본문 `[^라벨]` + 하단 `[^라벨]: 내용`         |
| 툴팁        | `[낱말](? 가리키면 나오는 짧은 설명)`           |
| 수식        | 인라인 `$E = mc^2$`, 블록 `$$ ... $$`           |
| 줄 끊기     | 줄 끝에 역슬래시 하나 또는 공백 둘              |
| 글자로 쓰기 | `\*`, `\[`, `` \` ``, `\$` — 표시 앞의 역슬래시 |
| 이미지      | `![alt](url "캡션")` — 단독 줄이면 `<figure>`   |
| 비디오      | `!video[alt](url)`                              |
| 임베드      | `!embed(https://...)`                           |
| 다이어그램  | ```` ```diagram {type=flow} ```` — `flow` · `sequence` · `tree` |
| 정리 환경   | `> [!THEOREM]`·`LEMMA`·`COROLLARY`·`PROPOSITION`·`DEFINITION`·`EXAMPLE`·`REMARK`·`PROOF` |
| 사이드노트  | 본문 `[^^라벨]` + 하단 `[^^라벨]: 내용` — 여백에 섭니다 |
| 정의 목록   | 용어 줄 + `:: 뜻` 줄 (콜론 둘)                  |
| 인용 출처   | 인용 마지막 줄 `> — 출처`                       |
| 그림 나란히 | ```` ```figures {cols=2} ```` + 그림 줄들       |
| 그림·표 목록 | `[toc:fig]` · `[toc:tbl]` — 그 계열의 목록      |
| 상호참조    | 캡션 `{#fig:이름}` + 본문 `[@fig:이름]` |
| 인용        | 본문 `[@key]` + `refs.bib` |
| 코드 속성   | ```` ```js {file=server.mjs, lines, hl=3-5;9} ```` |
| 외부 자료   | ```` ```table {src=data/x.csv} ````, `{src=...}`를 그래프·코드 펜스에도 |

본문 표기·표·그래프·다이어그램·툴팁의 확장 문법은 [SYNTAX.md](SYNTAX.md)에 따로 있습니다.

## 구조

읽는 자리를 둘로 갈랐습니다. `render/`는 원고 한 편을 HTML로 옮기는 일만 하고 파일시스템도 `dist/`도 모릅니다. `site/`는 그 결과를 모아 사이트 한 벌을 굽습니다.

```
render/       원고 한 편 → HTML (순수 함수, DOM·파일시스템 미사용)
  index.mjs     Markdown 파서와 frontmatter 파싱
  table.mjs     확장 표 문법 (병합·정렬·배경·테두리·캡션)과 자료 파일을 읽는 표 펜스
  code.mjs      코드 펜스 (파일명·줄번호·줄 강조·diff·외부 파일)
  numbering.mjs 그림·표·식·코드·정리의 번호와 상호참조, 그림·표 목록
  bib.mjs       BibTeX 파싱과 APA 참고문헌
  data.mjs      CSV·TSV → 파이프 격자와 같은 자료 격자
  image.mjs     이미지 파일 머리에서 내재 크기 판독 (PNG·JPEG·GIF·WebP·AVIF·SVG)
  attrs.mjs     {key=value} 속성 읽기 (표·그래프·다이어그램·코드가 공유)
  escape.mjs    HTML·SVG 이스케이프
  chart/        그래프 문법 → SVG
    index.mjs     조립 (여백 2회 측정 → 축 → 마크 → <figure>)
    axes.mjs      읽기 방식별 축 구성 (스케일·눈금 라벨·좌표 변환)
    parse.mjs     펜스 → 격자·옵션·캡션, 네 가지 읽기 방식
    scale.mjs     linear · log · category 스케일과 1·2·5 눈금
    frame.mjs     여백 계산, 축·눈금·격자, 범례
    text.mjs      DOM 없이 글자 폭 추정 (여백을 잡으려면 필요)
    channels.mjs  무채색 구분 채널 (선 모양·마커·명도·빗금)
    plots/xy.mjs    line step area stackplot scatter errorbar stem
    plots/bar.mjs   bar barh hist broken_barh
    plots/stat.mjs  box violin ecdf
  diagram/      다이어그램 문법 → SVG
    index.mjs     조립 (펜스 → 배치 → <figure>)
    parse.mjs     세 문법이 나눠 쓰는 노드·화살·라벨 읽기
    shapes.mjs    상자·화살머리·꺾은선·라벨과 글자 폭에 맞춘 상자 크기
    flow.mjs      층 배치 (최장 경로, 순환은 바깥으로 돌림)
    sequence.mjs  참가자 생명선과 시간축
    tree.mjs      들여쓴 개요 → 층별 트리
site/         글 묶음 → 사이트 한 벌
  build.mjs     posts/*.md → dist/ 정적 생성
  pages.mjs     홈(쪽 나눔) / 글 / 분류 / 키워드 / 시리즈 / 연도 / 404 페이지
  bake.mjs      렌더된 HTML에 수식(KaTeX)과 문법 강조(highlight.js)를 굽는다
  webp.mjs      sharp가 있으면 사진의 webp 쌍둥이를 굽고 <picture>로 감싼다 (없으면 아무 일도 하지 않음)
  og.mjs        공유 카드 SVG
  lint.mjs      콘텐츠 점검 (순수 함수, 빌드가 재료를 넘긴다)
  feeds.mjs     rss.xml / sitemap.xml / robots.txt 생성
  minify.mjs    배포용 CSS·JS 축소 (주석·공백만 걷어내는 상태 기계)
  server.mjs    dist/ 정적 서버 (ETag, brotli·gzip, 보안 헤더)
index.html    <!--%TITLE%--> · <!--%HEAD%--> · <!--%APP%--> 플레이스홀더를 가진 템플릿
style.css     전체 스타일
app.js        점진적 향상만 담당 (툴팁, 복사 버튼, 검색, 테마 토글)
posts/        글 원본
draft/        아직 내보내지 않는 글. 빌드는 읽지 않는다
data/         글이 가리키는 자료 파일 (CSV·TSV)
assets/       글이 가리키는 그림·영상
refs.bib      참고문헌 원본 (BibTeX)
fonts/        배포되는 웹폰트. 본문 로마자는 cmu-*(네 굵기 × 라틴/확장),
              한글은 sm-base(화살표·한글·가나·부호)와 sm-han(한자),
              코드는 geist-mono와 pretendard-code(코드 속 한글)
tools/        배포에 들어가지 않는 것. 글꼴 원본과 쪼개는 스크립트
              (split-font.sh: 본문 한글, serif-font.sh: 본문 로마자,
               code-fonts.sh: 코드 글꼴)
test/         파서 · 빌드 · 서버 · 문법 · 콘텐츠 테스트
```

`dist/`는 전부 생성물이므로 버전 관리하지 않습니다. 배포는 `dist/`를 정적 호스팅에 올리거나 `site/server.mjs`로 서빙하면 됩니다.

## 생성물

| 경로            | 내용                                              |
| --------------- | ------------------------------------------------- |
| `/`             | 최근 20편 + 분류 · 시리즈 · 연도 목록             |
| `/page/{n}/`    | 홈의 둘째 쪽부터. 20편을 넘길 때만 생긴다         |
| `/{slug}/`      | 글 본문                                           |
| `/{연도}/`      | 그 해의 글                                        |
| `/category/{c}/`| 카테고리별 목록                                   |
| `/keyword/{k}/` | 그 키워드를 단 글 목록                            |
| `/series/{s}/`  | 시리즈 목차                                       |
| `/og/{slug}.svg`| 공유 카드                                         |
| `/404.html`     | 서버가 미존재 경로에 반환하는 페이지              |
| `/rss.xml`      | RSS 2.0, `content:encoded`에 본문 전체 (절대 URL) |
| `/sitemap.xml`  | 모든 라우트 + `lastmod`                           |
| `/robots.txt`   | 크롤러 허용 + sitemap 위치                        |
| `/posts.json`   | 본문 없는 메타데이터 목록 (외부 소비용, 렌더링에는 미사용) |
| `/search.json`  | 검색용 본문 색인 (`{slug, text}`). 검색창을 처음 열 때만 받습니다 |
| `/style.{해시}.css` `/app.{해시}.js` | 내용 해시가 붙은 이름. 내용이 바뀌면 주소가 바뀌므로 1년 `immutable`로 캐시합니다 |
| `/katex.{해시}.css` `/katex/*.woff2` | 수식이 있는 글이 하나라도 있을 때만 나옵니다. 수식 글자 모양을 지는 것이고, 조판은 이미 HTML에 박혀 있습니다 |

## 색

색의 출처는 `tools/theme.json` 한 벌입니다. 어두운 테마가 거기 적힌 그대로이고, 밝은 테마는 `tools/theme.mjs`가 파생합니다 — 사람이 고른 밝은 값은 하나도 없습니다.

```bash
node tools/theme.mjs          # 바뀔 내용을 보여만 준다
node tools/theme.mjs --write  # style.css의 표시 사이를 갈아 끼운다
```

파생 규칙은 한 줄입니다. oklch의 밝기를 뒤집되, 축이 50%가 아니라 `base`와 `text`의 한가운데입니다. 50%로 뒤집으면 바탕이 15%에서 85%로 가서 종이가 아니라 신문지가 됩니다. 축을 옮기면 바탕이 종이가 되고 어두운 벌의 명도 간격이 그대로 옮겨옵니다.

`style.css`의 팔레트 블록은 생성기가 쓰는 자리라 손으로 고치지 않습니다. 고치면 `npm test`가 깨집니다 — 시험이 박힌 값과 생성기의 출력을 맞춰 봅니다. 사다리 열두 단은 채도가 전부 0이고, 출처에 함께 있는 액센트 여덟 색은 가져오지 않았습니다. 위계를 색이 아니라 크기와 굵기로 만드는 것이 이 종이의 규칙이기 때문입니다.

## 글꼴

본문 로마자는 CMU Serif, 한글은 신명조입니다. 둘 다 `dist/`에서 나가므로 어느 페이지도 남의 서버에 글꼴을 청하지 않습니다.

CMU Serif는 Computer Modern의 유니코드판이며 SIL Open Font License로 배포됩니다. 출처는 [CTAN](https://www.ctan.org/tex-archive/fonts/cm-unicode)이고 라이선스는 `fonts/cmu-OFL.txt`에 있습니다. `--serif`는 CMU Serif를 우선 사용하고 Times New Roman을 대체 글꼴로 둡니다. 네 벌(보통·굵게·기울임·굵은 기울임)이 각자 제 파일을 가지므로 브라우저가 굵기나 기울기를 흉내 낼 일이 없고, 굵은 글씨가 없는 글은 그 파일을 받지 않습니다. 라틴 확장은 `unicode-range`가 달라 그 글자가 실제로 나오는 글에서만 내려옵니다.

| 파일 | 구간 | 크기 |
| --- | --- | --- |
| `fonts/cmu-regular.woff2` 외 3벌 | 라틴 기본, 일반 구두점 | 약 25–27 KB |
| `fonts/cmu-*-ext.woff2` 4벌 | 라틴 확장, 통화 기호 | 약 23–34 KB |

화살표 구간(`U+2190–21FF`)은 신명조가 통째로 집습니다. `↩`와 `∎`은 어느 쪽에도 없어 시스템 글꼴이 맡습니다.

한글 쪽도 두 벌로 나뉘어 있습니다. 원본 `tools/fonts/sm.woff2`는 1.7MB이고 그중 81%가 한자입니다. `unicode-range`가 겹치지 않는 두 `@font-face`로 갈라 두면 브라우저는 페이지에 실제로 나온 글자가 든 쪽만 받습니다.

| 파일 | 담는 것 | 크기 |
|---|---|---|
| `fonts/sm-base.woff2` | 화살표, 한글 음절, 호환 자모, 가나, 중일한 부호, 전각·반각 | 254 KB |
| `fonts/sm-han.woff2` | 한자, 한자 호환 | 1369 KB |

`index.html`이 미리 받는 것은 `sm-base`와 `cmu-regular` 둘뿐입니다 — 어느 글에나 나오는 몫입니다. 한자가 나오는 글에서만 `sm-han`이, 굵은 글씨가 있는 글에서만 `cmu-bold`가 내려옵니다. 글꼴에 아예 없는 문자(아랍 문자, 데바나가리 등)는 `--serif` 스택의 뒤쪽, 즉 시스템 글꼴이 맡습니다.

쓰인 글자만 남기는 방식은 쓰지 않습니다. 그렇게 하면 새 글에 처음 나온 글자가 조용히 시스템 글꼴로 떨어집니다.

글꼴을 바꿨을 때는 `tools/split-font.sh`(한글)와 `tools/serif-font.sh`(로마자)를 돌려 다시 만듭니다. `serif-font.sh`는 CMU Serif 원본 OTF가 없으면 CTAN에서 내려받습니다. 원본은 빌드에 필요하지 않아 Git에서 제외하고, 생성한 WOFF2와 라이선스를 보관합니다. `fonttools`가 필요하고(`pip install fonttools brotli`), 배포 이미지에는 파이썬이 없으므로 결과물을 저장소에 넣습니다. 범위를 고칠 때는 `style.css`의 `@font-face`와 스크립트 양쪽을 같이 고쳐야 합니다.

## 배포본 최적화

빌드가 `dist/`를 만들 때 하는 일입니다. 원본 파일은 손대지 않습니다.

- **주석·공백 제거** — `site/minify.mjs`가 CSS와 자바스크립트를 깎습니다. 정규식이 아니라 한 글자씩 읽는 상태 기계라, 문자열·템플릿·정규식 리터럴·`url()` 안의 주석처럼 생긴 글자를 지우지 않습니다. 깎은 결과가 문법을 깨뜨리면 원본을 내보냅니다.
- **수식과 문법 강조를 빌드에서 굽습니다** — 예전에는 KaTeX와 highlight.js를 CDN에서 받아 브라우저가 페이지를 다시 그렸습니다. 지금은 `site/bake.mjs`가 렌더된 HTML에 조판된 수식과 토큰으로 나뉜 코드를 박아 내보냅니다. 세 가지가 따라옵니다. JavaScript가 꺼져 있어도 수식이 보이고, 어느 페이지도 남의 서버에 요청을 보내지 않으며, 코드 배색이 우리 것이 되어 `style.css`의 무채색 규칙을 따릅니다. 수식이 있는 페이지만 글꼴을 지는 `katex.{해시}.css`를 받고, 그것도 우리 `dist/`에서 옵니다.
- **읽지 못한 수식은 남습니다** — KaTeX가 읽지 못한 식은 원본이 점선 밑줄과 함께 그 자리에 남고 빌드가 경고합니다. 조용히 사라지는 것보다 무엇을 잘못 썼는지 보이는 편이 낫습니다. 그래프가 읽히지 않을 때 코드 블록으로 떨어지는 것과 같은 규칙입니다.
- **이미지 크기를 박습니다** — `render/image.mjs`가 PNG·JPEG·GIF·WebP·AVIF·SVG의 머리에서 내재 크기를 읽어 `width`·`height`로 씁니다. 크기가 없으면 그 자리가 두 번 배치되고 그때마다 아래가 튑니다. 여러 해상도(`srcset`) 생성은 하지 않습니다.
- **사진에는 webp 쌍둥이** — `sharp`가 설치된 기계에서만 도는 단계입니다. `assets/` 아래의 png·jpeg마다 `.webp`를 굽고, 그 그림을 가리키는 `<img>`를 `<picture>`로 감쌉니다.

  ```html
  <picture><source srcset="/assets/a.webp" type="image/webp">
  <img src="/assets/a.png" alt="…" width="640" height="400" loading="lazy" decoding="async"></picture>
  ```

  - **없으면 아무 일도 하지 않습니다.** `sharp`는 네이티브 꾸러미라 `package.json`에 넣지 않았습니다. 이 저장소는 컴파일러를 열어 본 적 없는 기계에서도 빌드되어야 합니다. 굽고 싶으면 `npm i -D sharp` 한 줄이고, 없는 기계는 원본 그림을 그대로 내보냅니다 — 나가는 페이지는 `<source>` 한 줄만 다릅니다.
  - **원본은 남습니다.** 지우고 주소만 바꾸는 편이 작지만, 그러면 페이지가 굽는 단계에 매달립니다. 원본이 `<picture>`의 물러설 자리로 남아 있어야 두 기계가 같은 글을 냅니다.
  - **원본보다 큰 쌍둥이는 쓰지 않습니다.** 그런 파일은 저장소에 한 장을 더할 뿐, 읽는 쪽에 느린 쪽을 건넵니다.
  - **SVG·GIF는 굽지 않습니다.** 벡터는 굽을 것이 없고(글이라 `.br`·`.gz`가 맡습니다), GIF는 움직임을 지고 있습니다.
  - **피드는 원본만 가리킵니다.** RSS는 상대 주소를 절대 주소로 고쳐 내보내는데, 그 손이 `<source srcset>`까지 닿지 않기 때문입니다.
- **미리 압축** — 글로 된 파일마다 `.br`과 `.gz`를 옆에 둡니다. 서버는 요청마다 다시 압축하는 대신 그것을 그대로 흘려보냅니다. 한 번만 치르는 값이므로 빌드는 brotli 최고 단계와 gzip 9단계를 씁니다. `Accept-Encoding`에 `br`이 있으면 brotli를, 없으면 gzip을 보냅니다 — brotli 쪽이 확실히 작지만(rss.xml에서 31%, index.html에서 24%) 못 받는 상대가 아직 있어 두 벌을 둡니다. 압축본이 없으면 그 자리에서 압축하므로, 개발 중에도 동작이 달라지지 않습니다.
- **글꼴도 내용 지문으로** — `fonts/`가 1년 `immutable`인데 이름이 고정이면 글꼴을 바꿀 방법이 없습니다. 이제 `sm-base.<해시>.woff2`이고, 그 이름을 아는 것은 `style.css`, 그 `style.css`의 이름을 아는 것은 `index.html`입니다.

## 검색

머리글의 `Search` 단추, `/`, `Cmd/Ctrl+K` 중 아무 것으로나 엽니다. 창을 처음 열 때 `posts.json`과 `search.json`을 한 번 받아 두고, 그 뒤로는 입력할 때마다 메모리에서 훑습니다.

- **찾는 자리** — 제목·초록·분류·키워드가 먼저고, 본문에서만 걸린 글이 그 뒤에 붙습니다. 본문은 넓게 걸리므로 뒤로 두지 않으면 손으로 쓴 제목이 묻힙니다.
- **본문을 따로 둔 이유** — 검색을 열지 않는 사람이 글 전체를 받는 일이 없어야 합니다. `posts.json`은 목록 그대로 가볍고, 본문은 `search.json`이 집니다. 이 요청만 실패하면 제목과 초록까지로 좁혀서 그대로 돌아갑니다.
- **본문에서 빠지는 것** — 코드 울타리, 수식, 그림·영상은 글이 아니라 자료라 색인에서 빠집니다. 각주는 표시만 걷고 글은 남깁니다. 붙임표는 그대로 두므로 `step-ca`라고 친 대로 걸립니다.
- **초성** — `ㅇㄹ`로 `인류`를 찾습니다. 질의가 모두 초성일 때만 이 길로 갑니다.
- **왜 걸렸는지** — 맞은 자리를 굵게 냅니다. 초성으로 찾았을 때도 제목의 해당 글자가 굵어집니다. 제목에도 초록에도 없으면 본문에서 걸린 대목을 잘라 함께 보입니다.

## 다국어

글마다 앞머리에 `lang:`을 적을 수 있고, 그 값이 `<html lang>`이 됩니다. 적지 않으면 `ko`입니다. 스크린 리더가 제 소리로 읽고 브라우저가 제 규칙으로 줄을 나누는 데 쓰입니다.

캐시 정책은 세 가지입니다. 해시가 붙은 자산과 `fonts/`·`assets/`는 1년 `immutable`, HTML은 `no-cache`(매번 재검증), 그 밖의 `.css`·`.js`는 1시간. HTML이 매번 재검증되므로 배포 직후 첫 요청에서 새 자산 주소를 받고, 읽는 쪽에서 강력 새로고침을 할 일이 없습니다. `DEV=1`이면 전부 `no-cache`입니다.

## 번호와 상호참조

캡션의 번호는 렌더러가 매깁니다. 손으로 적으면 글 중간에 그림 하나를 끼울 때마다 뒤의 모든 캡션을 다시 써야 합니다.

```markdown
: {#fig:ca-tree} CA 계층 비교 | n=120

본문에서 [@fig:ca-tree]를 보면 됩니다.
```

- **번호가 붙는 것** — 캡션이 있는 그림과 표는 언제나 번호를 받습니다. 그림은 이미지·영상·그래프·다이어그램이 한 계열을 나눠 씁니다. 식과 코드는 이름표를 붙인 것만 번호를 받습니다 — 부를 일이 없는 번호를 여백에 세워 둘 이유가 없습니다. 정리 환경은 언제나 번호를 받습니다.
- **번호를 세는 차례** — 종류마다 따로 세고, 글에 실린 차례대로 매깁니다. 이름표도 종류마다 따로 살아서 `{#fig:비용}`과 `{#tbl:비용}`이 한 글에 같이 있어도 됩니다.
- **부르는 법** — `[@fig:이름]`은 "그림 3"이 되고 그 자리로 가는 링크가 됩니다. `[@#fig:이름]`은 이름 없이 번호만 냅니다. 앞에서 뒤를 불러도 됩니다.
- **절도 부를 수 있습니다** — `## 제목 {#sec:setup}`으로 이름을 붙이고 `[@sec:setup]`으로 부르면 제목의 글자가 링크로 나옵니다. 절에는 번호를 쓰지 않기 때문입니다.
- **없는 이름을 부르면** 글자 그대로 남고 lint가 잡습니다. 오타가 조용히 사라지지 않습니다.
- **번호를 빼려면** 캡션에 `{nonumber}`를 씁니다.

## 참고문헌

`refs.bib`(BibTeX)에 출처를 모아 두고 본문에서 key로 부릅니다.

```markdown
[@tls13]을 보면 됩니다. [@texbook, 42쪽]과 [@tls13; @rfc5280]도 씁니다.
```

- **본문에는 (저자, 연도)가 섭니다.** `[@tls13]`은 `(Rescorla, 2018)`이 되고 목록의 그 줄로 가는 링크가 됩니다.
- **목록은 둘, 조판은 하나입니다.** 각주는 "주석"에, 출처는 "참고문헌"에 섭니다. 각주는 이 글이 곁들이는 말이고 출처는 이 글이 기댄 남의 글이라 갈라 두되, 테두리·크기·제목 꼴은 같습니다.
- **참고문헌은 APA입니다.** `저자 (연도). 제목. 실린 곳.` 꼴로, 번호 없이 저자의 성으로 정렬합니다. 항목 전체가 그 출처의 주소로 가는 링크이고, 주소가 없는 출처는 글자로만 남습니다.
- **목록의 ↩는 본문으로 돌려보냅니다.** 각주와 출처 모두 답니다. 여러 번 부른 것은 처음 부른 자리로 갑니다.
- **부른 것만** 하단 목록에 나옵니다. 쓰지 않은 항목은 `.bib`에 남아 있어도 나가지 않습니다.
- 없는 key는 글자 그대로 남고 lint가 잡습니다. 한 괄호에 여럿을 부를 때 하나라도 모르면 그 괄호 전체가 글자로 남습니다 — 반쯤 바뀐 인용은 오타를 감추기만 합니다.
- `bib:` 앞머리로 글마다 다른 파일을 가리킬 수 있습니다.

## 시리즈

여러 편으로 나눈 글은 앞머리에 `series`와 `part`를 적습니다.

- `/series/{슬러그}/`에 목차가 생기고, 글 머리에 "3편 중 2편" 띠가 붙습니다.
- 이전·다음은 **시리즈를 먼저** 따릅니다. 그다음이 같은 분류, 마지막이 날짜입니다.
- 마지막 편의 "다음 글"은 같은 시리즈로 돌아가지 않습니다. 날짜순으로는 1편이 더 새 글일 수 있고, 그 편들은 목차에서 이미 닿습니다.
- 편이 하나뿐인 시리즈에도 페이지가 생깁니다. 이어질 글을 예고하며 쓰기 시작하는 것이 보통이고, 두 번째 편이 나오는 날 주소가 생기는 것은 늦습니다.

## 콘텐츠 lint

`npm run lint`. 글이 늘고 분야가 갈리면 손으로 못 잡는 것들을 봅니다.

| 오류 | 경고 |
| --- | --- |
| 없는 이름표를 부른 상호참조, 두 번 쓰인 이름표 | 코드 블록으로 떨어진 그래프·다이어그램·표 펜스 |
| 참고문헌에 없는 인용 key | 부르지 않아 나가지 않은 사이드노트 |
| 읽을 수 없는 `{src=...}` 파일 | `alt` 없는 그림 |
| 없는 그림 파일, 없는 앵커, 없는 주소 | 정의되지 않은 참조식 링크 |
| 중복 slug, 빠진 `title`·`date`, 형식이 아닌 `date` | 본문에서 뽑아 쓴 한 줄 요약 |

빌드를 멈추지는 않습니다. 글을 쓰는 중에 막혀서는 안 되고, 잡는 것은 CI의 몫입니다. `npm run build`는 목록만 내고, `npm run lint`는 오류가 있으면 종료 코드 1을 냅니다.

## 공유 카드

빌드가 글마다 `/og/{slug}.svg`를 그립니다. 조판은 글 페이지와 같습니다 — 워드마크, 분류와 날짜, 크게 앉힌 제목, 아래의 키워드.

래스터화(PNG)는 하지 않습니다. 네이티브 이미지 라이브러리와 배포 이미지 안의 글꼴 스택이 필요하고, 그것은 미리보기 한 장 값으로 너무 비쌉니다. **알려진 한계로 적어 둡니다: SVG를 그리지 않는 크롤러에서는 예전처럼 그림 없이 나옵니다.** SVG를 그리는 쪽과 파일을 직접 여는 사람은 실제 카드를 봅니다.

## 타이포그래피 규칙

- 사이드노트는 넓은 화면(1180px 이상)에서만 오른쪽 여백으로 나갑니다. 그 아래에서는 그 자리에 작은 덩이로 앉고, 인쇄물에서는 여백에 남습니다. 어느 쪽이든 스크립트가 필요하지 않습니다.
- 본문 줄 간격 160~200% 유지 (본문 180%, 초록·목차 170%, 코드 블록 160%). 제목은 의도적으로 110~130%.
- 본문 문단은 양쪽정렬(`text-align: justify`)에 첫 줄 1em 들여쓰기. 제목 뒤 문단도 새 문단이므로 들여씁니다.
- 목록·표·그림·코드 블록·수식 블록·임베드·인용·구분선 **직후** 문단만 들여쓰지 않습니다. 앞 블록에서 이어지는 설명이기 때문입니다.
- 한글이 단어 중간에서 끊기지 않도록 `word-break: keep-all`, 긴 URL만 `overflow-wrap: break-word`로 처리합니다.

## 라이선스

이 저장소의 소스 코드는 **Apache License 2.0**입니다. 전문은 `LICENSE`에 있습니다.

`fonts/`의 글꼴 파일은 **이 라이선스가 덮지 않습니다.** 글꼴마다 제 라이선스를 그대로 지니며, 출처와 조건은 `NOTICE`에 정리해 두었습니다.

- CMU Serif·Geist Mono·Pretendard는 SIL Open Font License 1.1이고, 라이선스 전문을 `fonts/`에 함께 둡니다.
- **조선신명조(`sm-base.woff2`, `sm-han.woff2`)는 라이선스 전문이 없습니다.** 조선일보 배포 글꼴을 `tools/split-font.sh`로 서브셋한 결과물이라, 재배포·변형 조건을 저장소가 보증하지 못합니다. 포크하거나 다시 배포할 때는 배포처의 현재 조건을 확인하고, 허용되지 않으면 두 파일을 지우십시오. 지워도 `--serif` 스택이 시스템 바탕으로 물려받으므로 페이지는 깨지지 않습니다.

`posts/`와 `draft/`의 글은 저장소에 담지 않습니다(`.gitignore`). 코드만 공개하고 글은 각자의 기계에 둡니다.
